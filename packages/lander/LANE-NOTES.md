### Ports (`src/ports.ts`), for L3 to L6

- `HubPort`: claim, getClaim, heartbeat, release (the lease); next, admit, advance, resolve, reportTrunk, pause, lander (the lander routes); landings, landing, tasks, decisions, status (reads); post (direct messages); events (long-poll, and the hub epoch). Failures reject with `HubCallError {code, status, details}`: the hub's code (`not_lander`, `landing_stale`, `approval_missing`, `claim_conflict` with `details.conflicts`, ...), or `unavailable` (no answer; `status: null`, so the request may have been applied), `bad_response`, `aborted` (the caller's signal), `http_error`. `.unavailable` is true for no answer and for HTTP 5xx. `isHubError(err, ...codes)`.
- `GitPort`: gitops bound to the mirror and its remote, plus `fetch(refspecs) → {kind: 'ok' | 'missing' | 'error'}`, `treeOf`, `commitInfo` (author with a raw date, ready for `commitTree`), `commits(from, to, limit)` (oldest first, with the total), `pathHistory`, `mergeFile`, `deleteLocalRef`. `openGitPort({mirror, remote, env?})` in `git-port.ts`; bareness is detected.
- `ChecksPort.run(CheckRunRequest) → {status, report: CheckReport, logFile}` with `status` one of `passed`, `failed` (checks_failed), `timed_out` (check_timeout), `modified_tree` (checks_modified_tree), `trunk_moved` (requeue), `aborted`. `killOrphans()` for startup recovery.
- `ResolverPort` (`ResolveRequest` / `ResolveResult`) is a first cut for L5 to finish; a null resolver means stage 3 is skipped.
- `Clock` (`systemClock`), `FAULT_POINTS`, `Faults` (`noFaults`).

### Behaviour later steps (and other lanes) rely on

- **Config precedence:** flags, then env (`HUB_URL`, `HUB_PROJECT`, `HUB_TOKEN`, `HUB_LANDER_TOKEN`, `HUB_LANDER_ID`), then `<dir>/lander.json`, then defaults. Without `--dir`, the project (flag or `HUB_PROJECT`) names the default workdir `~/.agenthub/lander/<project with / → _>`; without either, ConfigError. `withTrunkDefaults(cfg, agenthubJson)` fills `hub`/`project` from trunk's `url`/`project` later. Every problem is a `ConfigError` (`exitCode = 2`).
- **lander.json** is opened, then checked with `fstat`: a regular file, owned by the lander's user, with no group or other permission bits at all (`mode & 0o077`). Unknown keys are refused; any key containing "anthropic" is refused with "only from the environment". Keys: `hub, project, token, landerToken, idPrefix, remoteUrl, committer` ("Name <email>" or `{name, email}`), `drivers` (`[{name, command, patterns}]`), `resolverCommand, resolverMaxPerHour, passEnv, checkWrapper, leaseTtlMs, pollTrunkMs`.
- **Secrets:** `ANTHROPIC_API_KEY`, `HUB_TOKEN` and `HUB_LANDER_TOKEN` are read and deleted from the environment first thing in `loadLanderConfig`, even when it then throws (the hub tokens too: defence in depth, so git and merge drivers don't inherit them either). They live on the config as non-enumerable properties (`JSON.stringify(cfg)` and spreads leave them out); `landerSecrets(cfg)` lists them for redaction.
- **Lander ids:** the prefix must be `lander/<name>`; `landerId(prefix)` appends `-<pid>-<4 hex>` and trims the name so the id always fits `AGENT_ID_RE`. The default prefix is `lander/<hostname>` with the host name made valid.
- **CLI flags** (`parseLanderArgs`, node:util `parseArgs`, strict): the §6.3.6 set, per command (`init`: `--remote --dir --hub --project`; `run`: the run flags plus `--once`; `doctor`: the run flags). `--driver name=CMD@pattern[,pattern...]` splits at the last `@`. Number flags take digits only, as hub-server does.
- **Hub client routes** (for H4 to match): `GET /lander` → `{lease, control}`; `GET /landings?status=a,b&agent=&task=&limit=` → `{landings}`; `GET /landings/:id` → `{landing}`; `GET /decisions?limit=N` → `{decisions}`; `POST /messages {to, body}` → `{message}`; `GET /events?since=&types=a,b&wait_ms=` (the client's timeout is the wait plus its own plus 5 s). Ids are URI-encoded into paths. Headers: `x-hub-agent`, `authorization: Bearer` (when set), `x-hub-lander-token` (when set); tokens are `#private` fields.
- **Checks env** (`checkEnvironment`): `PATH`, `LANG`, `LC_ALL` from the lander's env; `TZ=UTC`, `TERM=dumb`, `CI=1`, `npm_config_cache=<dir>/npm-cache` (trunk's `checkEnv` may override these); then `checkEnv`, then the `passEnv` values; then the deny rules over all of it: `HUB_*`, `ANTHROPIC_*`, `GIT_*`, `SSH_AUTH_SOCK`, `SSH_AGENT_PID`, `SSH_ASKPASS`, `GH_TOKEN`, `GITHUB_TOKEN` never, and `*_TOKEN`, `*_KEY`, `*_SECRET`, `*_PASSWORD` only when named in `passEnv`; finally `HOME`, `TMPDIR`, `AGENTHUB_LANDING`, `AGENTHUB_TRUNK`, which nothing overrides.
- **Process groups:** the check runs detached (its own group). On timeout or abort: SIGTERM to the group, SIGKILL after `killGraceMs` (10 s). When the shell exits by itself, whatever it left running in the group gets the same treatment. Zombies don't count as alive (on Linux, from `/proc`): this machine's PID 1 reaps orphans slowly, and waiting on zombies cost seconds per run. `state.json` holds `{checks: [{pgid, landing, attempt, dir, at}]}` while a check runs. `killOrphans()` kills a recorded group only if the record is from this boot and (on Linux) one of the group's live processes has its cwd inside the run's dir, so a recycled pgid is never killed; then it clears the file.
- **Pass** = exit 0, no stop reason, and `git status --porcelain --untracked-files=no` empty (unless `allowDirtyTree`). A status git can't produce counts as modified (fail closed).
- **Output:** each line is ANSI-stripped (terminal semantics for `\r`), stripped of controls and bidi characters, redacted (a key block's lines are dropped), then written to `logs/<L-id>.<attempt>.log` (0600, capped at 10 MiB with a truncation line), kept for the tail (200 lines, 16 KiB) and scanned for failed tests (at most 50). Lines over 64 KiB are cut, at a space when there is one.
- **The run directory** `runs/<L-id>.<attempt>/` (wt, home, tmp) is removed after every run, pass or fail (read-only trees made writable first), and `git worktree prune` always runs, so a stale registration never blocks `worktree add`.
- **`passes_on_trunk`** is `true` only when T0's own trailers carry this hub's epoch and the same command hash; otherwise `null` (never `false`).
- **`reproduce`** follows design §2.2.8 exactly: `git fetch <remote> <cand ref> && git worktree add /tmp/agenthub-<L> <C> && (cd /tmp/agenthub-<L> && <check>)`. (The contract fixtures carry another, older shape in their example `reproduce` strings; the design wins, and the field is free text, so no amendment is needed.)
- **Commit message** (`commitMessage`): subject = the task title's first line, else the summary's, else `Landing L-n`, capped at 72 then ` (L-n)`; the summary sanitized (trailer lines, controls, bidi) and at most 4000; `Squashed from N commits:` with at most 20 listed (`- <sha12> <subject>`, subjects sanitized) and `- … and K more`; the trailers as the last paragraph in the §1.1 order. `Agenthub-Resolved` is `clean`, `structural <paths>`, `ai:<model> <paths>`, or both joined by `; ` (`resolvedValue`). `Agenthub-Approved: protected:sam, merged:maya` only when approvals were needed. A trailer value with a control character throws (it would be a lander bug).
- **Fix-it conflict reports** (`ConflictReporter`): hunks only for `content` conflicts, from `mergeFile` (stage 2 = trunk, 1 = base, 3 = yours), at most 10, each side capped at 80 lines or 4 KiB with a `… (N more lines)` line; `symbols: []` until L6. `trunk_changes` = `pathHistory(base, T0, path, 5)`, newest first. A commit is attributed to a landing only when its trailers carry this hub's epoch, a `<project>/L-n` landing, and that landing's `commit` equals the trailer's source (so a forged or other-database trailer reads as foreign: all nulls, the commit subject as summary). Decisions: the landing's task's, else the author's that name the file; 3 newest. Hub reads are shared across one attempt's files and are best effort; a part that fails is left empty (`onError` hears about it).
- **Send-back texts:** `nextSteps(code, ctx)` and `failureMessage(code, ctx)` cover every `LandingFailureCode`; `sendbackMessage`, `parkedMessage` and `aiLandedMessage` are the §2.2.9 direct messages. They quote no agent text (paths only, control characters replaced). "You keep your place (retry n of k)" uses the failed landing's `retry + 1` against `keepPlaceRetries`. `emptyReport()`.
- **Redaction** (`Redactor`, `redact`): exact values (4 characters or longer, longest first), then shapes: `sk-ant-…`, `gh[pousr]_…`, `github_pat_…`, `xox[abposr]-…`, `AKIA…`/`ASIA…`, `npm_…`, and PEM private-key blocks, also cut off at either end of a text.

### Behaviour later steps (and other lanes) rely on

- **Process.** `Lander.run({once})`: claim the lease (standby until granted), then startup recovery (kill orphaned check groups, remove `runs/*`, `git worktree prune`, drop fetched candidate refs), a GC pass, and a **startup trunk report** (so the hub has trunk's policy, the claim gate included, before the first admission, and reconciles anything found on trunk). Then the admission loop and the attempt loop run side by side until the lease is lost (claim again) or `stop()`. `--once`: one admission round, then one `next` (one attempt or one in-doubt resolution), then the lease is released. Trunk reports only ever go out at startup or from the attempt loop (attempt P1, the idle watch, the stale/in-doubt paths), never from admission, so two reports can't race and move the hub's trunk backwards.
- **Lease.** Claim `{files: [LANDER_LEASE_KEY], mode: exclusive, queue: true, ttl_ms, heartbeat_interval_ms, intent: 'lander on <host>'}`; the epoch comes from `GET /events?wait_ms=0` at each claim. Heartbeat every `min(15 s, ttl/4)` on an unref'd timer; a heartbeat answer without the lease claim as active, a `not_lander` from any write, or no acknowledgement for a whole ttl marks it lost and aborts its signal (which kills the check). Standby: heartbeats its queued claim, long-polls `claim.granted|expired|released`, reads `GET /claims/:id`. Self-fencing: `renew()` right before `advance {pushing}`, and `fresh()` (ack younger than ttl/3 on both clocks, else renew) before every trunk push try. A 401/403 on the claim is `LeaseRefused` (exit 2).
- **Admission** (`Admission.admitAll`): one trunk fetch (into `refs/agenthub/admit-trunk`) and one strict config read per round; invalid config pauses `config_invalid` and admits nothing. Per landing: land ref fetched and its tip checked (`not_pushed`), `landedBase`, `nothing_to_land` / `too_large` on the whole change, containment (`contains_unlanded` for another agent's terminal unlanded landing not on trunk; `waits_for` = the nearest live contained landing), then `admit` with `scope: null, mapper: null` (L6 adds symbols). **A stacked landing's `files`, holds and `protected` requirements cover only the work after the landing it waits for** (its landed base will be that commit); if that one doesn't land, the attempt's P3 finds the extra protected paths and asks then. Test-file warnings (§4.1 #8: deleted test files, or more lines removed than added in `*.test.*`, `*.spec.*`, `test_*.py`) go in `warnings`. Failures go through `admit {code, report}` (the CP1a amendment) and a direct message.
- **The attempt** (`runAttempt`): P1 fetches trunk, reads the config strictly (missing branch or invalid config: pause `config_invalid`, requeue `config_invalid`), fetches the land ref, then the trunk scan. A rewrite requeues `trunk_rewritten` (the hub pauses); foreign commits with `externalPushes: pause` pause `external_push` and requeue `lander_stopping` (the change isn't at fault). The first trunk report ever (the hub knows no trunk) names no commits. A landing handed back under this lease in a phase past `merging` (the process lost its attempt) is requeued `lander_stopping`. P2 `findLandingCommit(first_base, T0)`; `also_landed` = the same agent's failed/superseded/cancelled landings contained in H and not on trunk. P4: stage 3 runs only with `land.resolver.enabled` and a `ResolverPort`; enabled without one gives `resolver.outcome: 'skipped'` and a warning; `resolver_failed` when the resolver's outcome is `rejected_output`/`error` or the checks fail after an AI resolution (L5 fills this in). The fast path (P6) needs `candidate_checked`, the same `trunk_base`, the staged ref still at the candidate on the remote (fetched into the mirror if missing), the same tree and parent, and every requirement met; then it pushes without checks and reports the parked run's check. Staging failures: `rejected` pauses `push_rejected` and requeues; anything else requeues `remote_unavailable` (the failed-check staging for `reproduce` is best effort). `approval_missing` at `pushing` parks with the hub's `details.missing` added. P10 deletes the land ref atomically only if the remote still has it (an atomic push deleting a missing ref would fail whole). A `lander_error` (an unexpected exception) fails the landing unless it is in pushing (then it is left in doubt); three in a row pause `config_invalid` ("lander workdir unusable").
- **Fault points** fire at: `after-admit` (after each admit answer), `after-next` (first thing in an attempt), `during-merge` (after merge-tree), `during-checks` (from `onStarted`, the check running), `after-checks` (passed), `after-candidate-staged`, `after-pushing-ack`, `after-trunk-push` and `before-landed-ack` (both after the push went through, before `advance {landed}`), `after-landed-ack`. In-process `Faults.at` may return a promise; the pipeline awaits it (the tests hold an attempt there).
- **In-doubt resolution** (`resolveInDoubt`): on trunk (ancestry of the candidate, or the trailer identity from `first_base`) → `resolve {landed}`; trunk past `trunk_base`, or the staged candidate gone → `resolve {requeue}`; trunk at `trunk_base` with the candidate staged → the same push, **unless landing is paused** (any reason: a refused push waits for `hub lander resume`, then `next` hands it back and the same candidate is pushed). Stale again → look again (3 rounds).
- **Shutdown** (`stop()`, SIGTERM/SIGINT in the CLI): the attempt's signal aborts (the check is killed), a running non-pushing landing is requeued `lander_stopping`, a landing this process left in doubt is resolved first (bounded, 60 s), then the lease is released. A second signal exits at once (code 1).
- **GC** (`collectGarbage`, at every lease grant and hourly): grace periods `LAND_REF_GRACE_MS` 1 h, `CANDIDATE_GRACE_MS` 7 days, `ORPHAN_GRACE_MS` 24 h (by committer date; the object is fetched if the mirror lacks it), `LOG_KEEP_MS` 7 days. Another epoch's candidate refs are orphans. Live landings' refs are never deleted. The mirror's local land refs of non-live landings and all fetched candidate refs are dropped.
- **Mergiraf**: auto-detected on PATH when `drivers` is null; driver name `agenthub-structural`, command `<abs path> merge --git %O %A %B -s %S -x %X -y %Y -p %P -l %L`, patterns from `mergiraf languages --gitattributes`. Only used with trunk's `land.structural: auto`.
- **CLI.** `init --remote <url> [--dir] [--hub] [--project]`: the workdir 0700, `git clone --bare`, `remote.origin.fetch` unset, the operator's own `credential.helper` values copied into the mirror's config (the lander's git reads no global config), `lander.json` (0600, `remoteUrl`, and `hub`/`project` when given) if absent; an existing mirror of another remote is refused. `run`: the trunk branch is the mirror's HEAD (trunk's `land.trunk` can move it); `hub`/`project` default to trunk's agenthub.json `url`/`project`. `doctor`: lines `<level>  <check>: <detail>` with levels `ok`, `FAIL`, `warn`, `skip`, `note`; checks `git features` (probed in a scratch repo), `mirror`, `remote`, `trunk config`, `ref namespace` (a probe ref under `<P>cand/doctor/<8 hex>`, pushed then deleted), `structural` (a self-test that only the driver resolves: two functions appended to one file), `resolver` (informational until L5), `hub`, `lander token` (a `next` with a lease that can't exist must answer `not_lander`), `isolation` (warn without `checkWrapper`), `host rule` (a reminder); exit 1 on any `FAIL`. `resolve-anthropic` answers `cannot_resolve` until L5.

### Observations for other lanes (no action needed for L3)

- **Lane H:** `enterPushing` also requires the hub's own pending candidate-independent requirements, beyond the lander's `required` (design T5 names only `required`). A requirement asked at admission that no longer applies (the base moved) therefore blocks `pushing` until someone approves it; the lander parks with `details.missing` added, which is safe but asks a human again. Admission now scopes stacked landings so the common case doesn't hit it.
- **The `Agenthub-Approved` trailer** lists the approvals present when the candidate is built. A landing approved after it parked lands on the fast path with its already-checked candidate, whose message was written before the approval: the trailer is then absent (the approval audit in the hub has it). Rebuilding the commit would change the sha the approval and the checks bind to, so it is left as is.
