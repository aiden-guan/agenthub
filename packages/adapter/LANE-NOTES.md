- **Skipped reasons** (`SyncSkipReason`): `no_queue`, `sync_running`, `edit_in_flight`, `fetch_failed`, `git_operation`, `detached_head`, `landing_in_flight`, `hub_unavailable`, `lander_paused` (replays only, design §3.8), `merges_in_branch`, `changed_meanwhile`, `timeout`, and in merge mode `dirty` and `merge_refused`. - **Order inside step 6.** "Up to date" (trunk is an ancestor of HEAD) is checked before the dirty check, so a dirty worktree with nothing new is `up_to_date`, not `behind_dirty {behind: 0}`. ## A2 repair round 1

No dependency requests and no contract-amendment requests.

- **Untracked and ignored files are never overwritten or removed (major).** `git reset --keep` refuses for an untracked file but treats an ignored one, and an ignored directory where the target has a file, as expendable. Inside step 9's compare-and-swap, right before the reset, `inTheWay(head, target)` looks at every path the target adds (`diff-tree --name-status --no-renames`) and its leading directories: a file or symlink at such a path, a directory there holding anything untracked or ignored (`ls-files --others --directory --no-empty-directory`), or a file or symlink at a leading directory that isn't a tracked file the target removes, makes the sync refuse with `skipped: changed_meanwhile` and `paths` (directories as `dir/`); the record and backup ref are cleared as for any refused move. Tracked files are clean at that point, so a path HEAD lacks is untracked or ignored; prefixes are checked shortest first and never through a symlink. A tracked file replaced by a directory, or a tracked directory by a file, still syncs, and so does a new file inside an existing ignored directory. Residual, as the design's: a file written between that check and the reset.
- **Merge mode** checks the same way before `git merge`, against the merge's own result (`merge-tree --write-tree`, which places renames and conflict files where the merge would) and against trunk's tip, and answers `skipped: merge_refused` with `paths`. `git merge` also gets `--no-overwrite-ignore`, but git 2.43 honours it only for a fast-forward: an ort merge overwrote an ignored `.env` with it set (shown in the test).
- **Texts.** `hub_sync` names the files and says sync never overwrites or removes them, and to move them aside. Settle and the digest say it too (once per set of paths, through `sync-said`), and likewise `old_git`: neither state goes away by itself, so beyond the brief's "changed, conflicted or behind and dirty", settle also prints these two. The digest now adds its `Trunk:` line when the hub fails as well (the sync may have moved the worktree all the same).
- **pre-push guard** reads the remote ref as the second field from the end: git writes the local ref as typed, so `git push origin 'HEAD^{/fix the bug}:main'` shifted the fields and got through. Lines with fewer than four fields are skipped as before.
- **The lock** is written in full under a temporary name and hard-linked into place (link fails on an existing lock, as O_EXCL does; a file system without hard links falls back to `wx`), so it is never seen half-written. A lock whose contents can't be read as `{pid, at}` counts as held until 120 s after its mtime, never as abandoned at once. Temporary files of syncs that died are swept by the next lock holder after 120 s.
- **Recovery (step 0) runs under the lock**, after step 1, not before it: only the lock holder writes a record, so a racing sync can no longer clear the record a running sync has just written. Outcomes are unchanged (a stale record is still recovered first thing, `no_queue` included); the design's step order lists recovery first. Integrator: if the order in §2.3.5 is meant literally, this is the one place it differs.
- **The 15 s hook bound covers the whole hook.** `HOOK_DEADLINE_MS` (12.5 s from the hook's start, the rest for starting node) bounds settle and the digest: settle on UserPromptSubmit releases pending claims within its first 4 s (left over: kept for the next try), then syncs within `min(12 s, what is left)`; on other events releasing gets the whole 12.5 s. The digest's sync gets what is left but 4 s, which its heartbeat, status and stats share, each request bounded by the deadline. Within the sync the hub's answer (step 5) now leaves 1 s for the plan beyond the apply reserve, so a hub that never answers still lets a fast-forward through (before, its timeout ran into the reserve and the sync ended in `timeout`). Measured against a hub that never answers with `HUB_TIMEOUT_MS=30000`: settle with two pending claims about 10 s, the digest about 12.9 s.
- **Old git (design §4.5): fast-forward only, and notify.** With no `merge-tree --merge-base` (`gitops.features`), a branch with unlanded commits is `skipped: old_git` (detail: git's version) before any replay, and a dirty worktree is `behind_dirty` with `conflicts: null` ("may conflict (your git is too old to forecast it …)"); fast-forwards and fully landed branches move as before. Tested with a `git` shim on PATH that reports 2.39.2 and refuses `--merge-base`.
- **Markers in other checkouts.** When pre-edit writes a marker in a checkout other than the session's own (a file in another worktree or repository), it first notes that marker directory in the session's checkouts (`G/agenthub/elsewhere/<session>~<hash>`). Settle clears the thread's (SessionEnd: the session's) markers there too, and on SessionEnd drops the notes; notes older than 30 min go. Only `…/agenthub/inflight` directories are ever named in a note.
- `SyncOutcome` changes (adapter-owned, not in the contract): `behind_dirty.conflicts` is `string[] | null`; `skipped` has optional `paths`; `SyncSkipReason` gained `old_git`.

Layout:

Write is `whole_file_write`, NotebookEdit `notebook`, `symbols.enabled: false` `disabled`; a missing file, over 1 MiB, an ambiguous or missing `old_string`, an uncontained parse error, more than `maxSymbolsPerEdit` keys and an edit that changes no text are whole files.
