- **Skipped reasons** (`SyncSkipReason`): `no_queue`, `sync_running`, `edit_in_flight`, `fetch_failed`, `git_operation`, `detached_head`, `landing_in_flight`, `hub_unavailable`, `lander_paused` (replays only, design §3.8), `merges_in_branch`, `changed_meanwhile`, `timeout`, and in merge mode `dirty` and `merge_refused`. - **Order inside step 6.** "Up to date" (trunk is an ancestor of HEAD) is checked before the dirty check, so a dirty worktree with nothing new is `up_to_date`, not `behind_dirty {behind: 0}`. ## A2 repair round 1

No dependency requests and no contract-amendment requests.

- **Untracked and ignored files are never overwritten or removed (major).** `git reset --keep` refuses for an untracked file but treats an ignored one, and an ignored directory where the target has a file, as expendable. Inside step 9's compare-and-swap, right before the reset, `inTheWay(head, target)` looks at every path the target adds (`diff-tree --name-status --no-renames`) and its leading directories: a file or symlink at such a path, a directory there holding anything untracked or ignored (`ls-files --others --directory --no-empty-directory`), or a file or symlink at a leading directory that isn't a tracked file the target removes, makes the sync refuse with `skipped: changed_meanwhile` and `paths` (directories as `dir/`); the record and backup ref are cleared as for any refused move. Tracked files are clean at that point, so a path HEAD lacks is untracked or ignored; prefixes are checked shortest first and never through a symlink. A tracked file replaced by a directory, or a tracked directory by a file, still syncs, and so does a new file inside an existing ignored directory. Residual, as the design's: a file written between that check and the reset.
- **Merge mode** checks the same way before `git merge`, against the merge's own result (`merge-tree --write-tree`, which places renames and conflict files where the merge would) and against trunk's tip, and answers `skipped: merge_refused` with `paths`. `git merge` also gets `--no-overwrite-ignore`, but git 2.43 honours it only for a fast-forward: an ort merge overwrote an ignored `.env` with it set (shown in the test).
- **Texts.** `hub_sync` names the files and says sync never overwrites or removes them, and to move them aside. Settle and the digest say it too (once per set of paths, through `sync-said`), and likewise `old_git`: neither state goes away by itself, so beyond the brief's "changed, conflicted or behind and dirty", settle also prints these two. The digest now adds its `Trunk:` line when the hub fails as well (the sync may have moved the worktree all the same).
- **pre-push guard** reads the remote ref as the second field from the end: git writes the local ref as typed, so `git push origin 'HEAD^{/fix the bug}:main'` shifted the fields and got through. Lines with fewer than four fields are skipped as before.
- **The lock** is written in full under a temporary name and hard-linked into place (link fails on an existing lock, as O_EXCL does; a file system without hard links falls back to `wx`), so it is never seen half-written. A lock whose contents can't be read as `{pid, at}` counts as held until 120 s after its mtime, never as abandoned at once. Temporary files of syncs that died are swept by the next lock holder after 120 s.
- **Recovery (step 0) runs under the lock**, after step 1, not before it: only the lock holder writes a record, so a racing sync can no longer clear the record a running sync has just written. Outcomes are unchanged (a stale record is still recovered first thing, `no_queue` included); the design's step order lists recovery first. Integrator: if the order in §2.3.5 is meant literally, this is the one place it differs.
- **The 15 s hook bound covers the whole hook.** `HOOK_DEADLINE_MS` (12.5 s from the hook's start, the rest for starting node) bounds settle and the digest: settle on UserPromptSubmit releases pending claims within its first 4 s (left over: kept for the next try), then syncs within `min(12 s, what is left)`; on other events releasing gets the whole 12.5 s. The digest's sync gets what is left but 4 s, which its heartbeat, status and stats share, each request bounded by the deadline. Within the sync the hub's answer (step 5) now leaves 1 s for the plan beyond the apply reserve, so a hub that never answers still lets a fast-forward through (before, its timeout ran into the reserve and the sync ended in `timeout`). Measured against a hub that never answers with `HUB_TIMEOUT_MS=30000`: settle with two pending claims about 10 s, the digest about 12.9 s.
- **Old git (design §4.5): fast-forward only, and notify.** With no `merge-tree --merge-base` (`gitops.features`), a branch with unlanded commits is `skipped: old_git` (detail: git's version) before any replay, and a dirty worktree is `behind_dirty` with `conflicts: null` ("may conflict (your git is too old to forecast it …)"); fast-forwards and fully landed branches move as before. Tested with a `git` shim on PATH that reports 2.39.2 and refuses `--merge-base`.
- **Markers in other checkouts.** When pre-edit writes a marker in a checkout other than the session's own (a file in another worktree or repository), it first notes that marker directory in the session's checkouts (`G/agenthub/elsewhere/<session>~<hash>`). Settle clears the thread's (SessionEnd: the session's) markers there too, and on SessionEnd drops the notes; notes older than 30 min go. Only `…/agenthub/inflight` directories are ever named in a note.
- `SyncOutcome` changes (adapter-owned, not in the contract): `behind_dirty.conflicts` is `string[] | null`; `skipped` has optional `paths`; `SyncSkipReason` gained `old_git`.

Layout:

Write is `whole_file_write`, NotebookEdit `notebook`, `symbols.enabled: false` `disabled`; a missing file, over 1 MiB, an ambiguous or missing `old_string`, an uncontained parse error, more than `maxSymbolsPerEdit` keys and an edit that changes no text are whole files. - **`src/guard.ts`**: `stagedScope` reads `git diff --cached --raw -z --no-renames --no-abbrev`; a modification (`M`, regular file on both sides, a mapped extension, not excluded) is mapped HEAD blob → index blob (one `cat-file --batch-check` and one `--batch`; blobs over 1 MiB are whole), at most 200 files within 10 s, with at most 40 keys per file (the landing-diff limit of §1.10: a commit is closer to a landing than to one edit); every other path, and every path of a merge (`stagedPaths` with `merging`, as in Phase 1), is a whole file. With any symbol entry the check is `POST /claims/check {scope, mapper}` (`HubClient.checkScope`, batched by whole files); with none it is Phase 1's `{files}`.
- **`src/land.ts`** (A1 left "the scope belongs with A3"): `land` sends the change's symbol entries (base..HEAD mapped the same way, at most 4000 entries, whole files' worth) and **always the mapper** when symbols are on. See "Land needs the mapper" below.
- **`src/mcp.ts`**: `claim` takes `path#Symbol` (sent as `{scope, mapper}`); `hub_wait {files}` does too (`checkScope … 'auto'`, and a partial release's `scope` wakes it); `release` refuses `path#Symbol` with what to do instead (release by claim id). **`src/human.ts`**: `hub claim FILE#Symbol`, `hub release` refuses one. **`src/client.ts`**: `checkScope`, `claims({holder, file})`. **`src/cli.ts`** HELP.
- **`src/format.ts`**: `denyReason(…, ctx?)`, `postEditConflictText`, `guardConflictLines`, `landingPlace`, `keyName`, `claimNames`; claims and conflicts are named by symbol wherever they hold symbols (`formatClaim`, the digest's "Your claims", `formatConflict`, the claim/release/hub_wait results).
- **`src/sync.ts`**: `SyncPaths.edits` and `markerName`; `removeMarker` (so `clearMarkers`, stale markers and a denied edit) removes the edit state saved beside the marker.

Decisions other steps and the integrator build on:

- **`path#Symbol`.** Split at the last `#`; the suffix must pass `isValidSymbolKey` and the whole name must not be an existing file (`src/notes#1` stays a file).
- **The edit state** (design "`before` is saved beside the marker"): `G/agenthub/edits/<session>~<tool_use_id>` (the marker's own name), JSON `{v, session, tool, file, abs, before, after_sha256, symbols, mapper, at}`, written only for a granted symbol-level edit with a `tool_use_id`. It lives in its own directory, not in `inflight/`, because every file in `inflight/` counts as an edit in flight for sync. It goes with its marker (post-edit, settle, a denial, a stale marker after 30 min), and states older than 30 min are pruned on the next write.
- **post-edit** reads the state before it clears the marker. If the file's sha256 is the simulated `after`'s, nothing happens. Otherwise `changedSymbols(before, actual)`: the keys pre-edit's claim doesn't cover (`entryCovers`, same mapper) are claimed (`auto`, `queue: false`; the edit already ran, so the claim isn't pending). Granted: silent. Denied: PostToolUse `additionalContext` naming whose code it also changed ("revert that part, or coordinate with them (hub_post)"), with the untrusted label. When what the tool wrote maps only to the whole file (it broke a header), it says so ("maps only to the whole file (…), so it counts as a change of src/auth.ts#logout, which …") rather than that the edit changed the other agent's declaration. A hub that can't be reached: the context says the change isn't claimed.
- **Deny reasons.** Without symbols on either side and without a hold in the way, the text is Phase 1's word for word. Otherwise: `src/auth.ts#login is claimed by sam/claude-1 to "…" (expires in 5 min).`, the label, `The rest of src/auth.ts is free: logout, refreshToken, Auth, imports.` (declarations first, then `imports` and `top-level code`, at most 12), and `Edit those, message sam/claude-1 with hub_post, wait with hub_wait {"files": ["src/auth.ts#login"]}, or take another task.` (the wait names exactly the edit's keys). A hold: `src/auth.ts#login is being landed by maya/claude-1 (L-7, checks running, about 4 min); it frees when L-7 lands; call hub_sync then.` A Write over a file where others hold declarations: `Write replaces the whole file, and sam/claude-1 holds refresh in it, to "…" (expires in 2 min): use Edit for the parts you change.`; other whole-file edits: `This edit claims all of src/auth.ts (it leaves a syntax error outside any one declaration), and …`. A symbol that overlaps nothing the edit (or commit) asked for is in the way only by mapper gating, and says `(made by another version of agenthub, so it counts as the whole file)`.
- **"It frees when L-n lands"**, everywhere a hold is described (the Phase 2 text said "lands or comes back"): a landing that comes back gives its holds back to its holder as leases (§1.6, §0.3 #9), so the code doesn't free then. `landing-ux.test.ts` changed with it.
- **The guard's header** is Phase 1's unless declarations are named on both sides ("These staged changes touch code exclusively claimed by other agents:"); each line names the holder's entry (`src/auth.ts#logout — claimed by …`); a hold reads `— being landed by L-7 (sam/claude-1, C-9); it frees when L-7 lands`, and the intents note is left out when only holds are listed.
- **Land needs the mapper (found by `hooks-symbols.test.ts`).** The hub builds a landing's holds from the request's scope, its whole `files`, and the agent's continued claims through `entriesFor(c, req.mapper)`, which makes every symbol claim its whole file when the request has no mapper. Without A3's change, an agent holding `login` while another holds `logout` got `claim_conflict` at `land` (shown by the test with the scope switched off). So `land` sends `mapper` whenever symbols are on, even with no symbol entries.
- **For lane L (L6) and the integrator:** admission has the same need. With `scope: null, mapper: null` (L5), T2's `setHolds` re-scopes the holds to whole files and, under `claimGate: fail`, fails the landing with `claim_conflict` whenever another agent holds another declaration of a changed file. Symbol parallelism through landing needs L6's symbol scope (with its mapper) at admission. The e2e Phase 3 scenarios can only pass with both.
- **Fast extension filter.** `symbol-scope.ts` keeps the seven languages' extensions (§2.4) as a negative filter before loading tree-sitter; the package's `languageFor` decides for those. A language the package adds later is whole-file here until the list has it (the safe side).
- **Residual:** a Phase 1 hub ignores `scope` in `/claims/check`, so the guard's symbol check would pass there unchecked. The release notes already say hubs are upgraded before adapters (§6.7 step 6).
